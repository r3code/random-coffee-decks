# Random Coffee Decks

Каталог колод для приложения [Random Coffee Cards](https://github.com/r3code/random-coffee).

Каждая колода — это JSON-файл в папке [`decks/`](./decks/). Приложение загружает их с GitHub Pages при первом запуске и кэширует на 24 часа. После установки PWA работает офлайн.

## Быстрый старт

1. Создай JSON-файл в `decks/` с именем `<deckId>-<lang>.json` (например, `my-deck-ru_RU.json`)
2. Заполни обязательные поля: `deckId`, `name`, `questions`
3. Запушь в `main` — CI автоматически:
   - Проверит все колоды через [линтер](#правила-валидации)
   - Сгенерирует `index.json` (каталог для приложения)
   - Опубликует на GitHub Pages

## Формат колоды

### Обязательные поля

| Поле | Тип | Описание | Ограничения |
|------|-----|----------|-------------|
| `deckId` | `string` | Уникальный идентификатор колоды | Формат: `^[a-z0-9-]+-[a-z]{2}_[A-Z]{2}$` (например, `couples-ru_RU`). Должен заканчиваться на `-<lang>` |
| `name` | `string` | Название колоды (показывается в UI) | 1–128 символов |
| `questions` | `array` | Массив вопросов | Минимум 1 вопрос |

#### Вопрос (элемент массива `questions`)

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | `string` | Уникальный идентификатор вопроса **в пределах колоды** (например, `q1`, `c3`). Не должен дублироваться |
| `text` | `string` | Текст вопроса |
| `categoryId` | `string?` | Опционально. ID категории из поля `categories`. Если указан — должен существовать в `categories` |

### Опциональные поля

| Поле | Тип | Default | Описание |
|------|-----|---------|----------|
| `description` | `string` | `""` | Короткое описание колоды (1 строка) |
| `lang` | `string` | `"ru_RU"` | Язык колоды. Формат: `^[a-z]{2}_[A-Z]{2}$` |
| `baseDeckId` | `string` | `null` | Базовый ID колоды (для перевода/вариаций одной колоды) |
| `deckCategory` | `string` | `null` | Категория колоды. **Если указан** — должен быть из белого списка (см. ниже) |
| `version` | `number` | `1` | Версия колоды. При обновлении увеличивай, чтобы пользователи могли проверить обновления |
| `source` | `string` | `null` | URL колоды (для обновлений). CI проставляет автоматически, но можно задать явно |
| `orders` | `array` | авто-генерация | См. [поле orders](#поле-orders--порядок-вопросов) |
| `categories` | `object` | `null` | См. [поле categories](#поле-categories--категории-вопросов) |

#### Белый список `deckCategory`

Категория колоды — это slug, который приложение использует для бейджа и фильтра. Должен быть одним из:

| slug | Название | Иконка |
|------|----------|--------|
| `couples` | Для пар | ❤ |
| `first-date` | Знакомство | ☕ |
| `friendship` | Дружба | ∞ |
| `family` | Семья | ⌂ |
| `work` | Работа | ⚒ |
| `self` | Самопознание | ◉ |
| `party` | Группа | ✺ |

> **Важно:** этот же список живёт в `src/data/decks.js` основного приложения. Если меняешь здесь — поменяй и там.

### Поле `orders` — порядок вопросов

Порядок — это **детерминированная перестановка** вопросов. На двух устройствах, загрузивших одну колоду, порядок A всегда одинаковый — это и есть синхронизация.

#### Авто-генерация (default)

Если `orders` не указан, приложение генерирует 10 порядков A–J автоматически:
- PRNG с фиксированным seed `(index + 1) * 12345`
- Fisher-Yates shuffle
- Одинаковый на всех устройствах (детерминированный)

Это подходит для большинства колод — порядок не несёт смысловой нагрузки.

#### Кураторские порядки (опционально)

Если автор колоды хочет контролировать прогрессию (например, «от лёгкого к глубокому»), можно указать `orders` явно:

```json
"orders": [
  {
    "id": "order_1",
    "name": "A",
    "sequence": ["q3", "q1", "q5", "q2", "q4"]
  },
  {
    "id": "order_2",
    "name": "B",
    "sequence": ["q2", "q4", "q1", "q5", "q3"]
  }
]
```

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | `string` | Уникальный ID порядка в пределах колоды (например, `order_1`) |
| `name` | `string` | Короткое имя для UI (обычно буква: `A`, `B`, ..., `J`) |
| `sequence` | `array<string>` | Массив ID вопросов в нужном порядке. **Длина = кол-во вопросов**, без дубликатов |

**Рекомендации:**
- Делай 10 порядков (A–J) для consistency с авто-генерацией
- Если хочешь меньше — приложение покажет только указанные
- Каждый `sequence` должен содержать **все** question IDs ровно один раз

**Пример кураторского подхода:** колода «Спокойное начало» использует принцип «лёгкие (привычки) → глубокие (тишина)» — вопросы о рутине идут первыми, уязвимые вопросы — в конце.

---

### Поле `categories` — категории вопросов

Категории — это **внутренние** категории вопросов (не путать с `deckCategory`). Используются для цветовой подсветки вопросов в UI.

```json
"categories": {
  "love":      { "name": "Любовь", "color": "#ec4899" },
  "future":    { "name": "Будущее", "color": "#f59e0b" },
  "honesty":   { "name": "Честность", "color": "#3b82f6" }
}
```

| Поле | Тип | Описание |
|------|-----|----------|
| `<categoryId>` | `object` | Key — ID категории (используется в `question.categoryId`) |
| `.name` | `string` | Название категории (обязательно) |
| `.color` | `string` | HEX-цвет (обязательно, например `#ec4899`) |

Если вопрос ссылается на `categoryId`, которого нет в `categories` — линтер выдаст ошибку.

## Правила валидации

CI проверяет каждую колоду при пуше. Ошибки валидации блокируют деплой.

| Проверка | Описание |
|----------|----------|
| Валидный JSON | Файл должен быть корректным JSON |
| `deckId` обязателен | И соответствует формату `^[a-z0-9-]+-[a-z]{2}_[A-Z]{2}$` |
| `deckId` заканчивается на `-<lang>` | Например, `couples-ru_RU` с `lang: "ru_RU"` |
| `lang` соответствует формату | `^[a-z]{2}_[A-Z]{2}$` |
| `name` обязательно | 1–128 символов |
| `questions` — непустой массив | Минимум 1 вопрос |
| Каждый вопрос имеет `id` и `text` | `id` — уникальная строка в пределах колоды |
| `categoryId` валиден | Если указан — должен существовать в `categories` |
| `deckCategory` из белого списка | Если указан — `couples`, `first-date`, `friendship`, `family`, `work`, `self`, `party` |
| `orders[].sequence` правильной длины | Длина = кол-во вопросов, без дубликатов, все IDs существуют |
| `categories` имеют `name` и `color` | Каждая категория — объект с обоими полями |

## Примеры

### Минимальная колода

Минимум — `deckId`, `name`, `questions`. Всё остальное — default.

```json
{
  "deckId": "my-deck-ru_RU",
  "name": "Моя колода",
  "questions": [
    { "id": "q1", "text": "Что для тебя важно?" },
    { "id": "q2", "text": "О чём ты мечтаешь?" },
    { "id": "q3", "text": "Что тебя вдохновляет?" }
  ]
}
```

Приложение само добавит `lang: "ru_RU"`, сгенерирует 10 порядков A–J, без категорий.

---

### Колода с категориями

```json
{
  "deckId": "friends-ru_RU",
  "lang": "ru_RU",
  "deckCategory": "friendship",
  "name": "Для друзей",
  "description": "Для старой дружбы — воспоминания, ценности, что-то новое",
  "version": 1,
  "questions": [
    { "id": "q1", "text": "Какое воспоминание о нас тебе дороже всего?", "categoryId": "memories" },
    { "id": "q2", "text": "Что ты ценишь в нашей дружбе?", "categoryId": "values" },
    { "id": "q3", "text": "Что нового ты узнал обо мне за последний год?", "categoryId": "discovery" }
  ],
  "categories": {
    "memories":  { "name": "Воспоминания", "color": "#8b5cf6" },
    "values":    { "name": "Ценности", "color": "#10b981" },
    "discovery": { "name": "Новое", "color": "#3b82f6" }
  }
}
```

Порядки A–J сгенерируются автоматически (детерминированно).

### Колода с кураторскими порядками

Когда автор хочет контролировать прогрессию диалога:

```json
{
  "deckId": "couples-calm-start-ru_RU",
  "lang": "ru_RU",
  "deckCategory": "couples",
  "name": "Спокойное начало",
  "description": "Тёплые вопросы для тихих вечеров вдвоём",
  "version": 2,
  "questions": [
    { "id": "q1", "text": "Что ты чувствуешь, когда мы вместе молчим?", "categoryId": "silence" },
    { "id": "q2", "text": "Как ты понимаешь, что я тебя люблю?", "categoryId": "feelings" },
    { "id": "q3", "text": "Что ты ценишь в нашей повседневной рутине?", "categoryId": "habits" },
    { "id": "q4", "text": "Какую привычку или ритуал ты бы хотел создать для нас?", "categoryId": "habits" },
    { "id": "q5", "text": "Что ты думаешь о нашем будущем?", "categoryId": "feelings" }
  ],
  "orders": [
    { "id": "order_1", "name": "A", "sequence": ["q3", "q4", "q2", "q5", "q1"] },
    { "id": "order_2", "name": "B", "sequence": ["q2", "q3", "q4", "q1", "q5"] },
    { "id": "order_3", "name": "C", "sequence": ["q4", "q3", "q2", "q5", "q1"] }
  ],
  "categories": {
    "silence":  { "name": "Тишина", "color": "#8b5cf6" },
    "habits":   { "name": "Привычки", "color": "#f59e0b" },
    "feelings": { "name": "Чувства", "color": "#ec4899" }
  }
}
```

Здесь порядок A начинается с лёгких вопросов о привычках (q3, q4), переходит к чувствам (q2, q5), и заканчивается самым уязвимым — тишиной (q1). Это создаёт мягкую прогрессию «от бытового к глубокому».

## Как работает приложение

1. **При первом запуске** приложение делает `fetch('https://r3code.github.io/random-coffee-decks/index.json')` — получает список всех колод (deckId, name, description, questionsCount, url)
2. **Кэширует** каталог в `localStorage` на 24 часа (`catalog_cache` ключ)
3. **При клике «Загрузить»** на колоду — `fetch(url)` загружает полный JSON колоды, сохраняет в `coffee_custom_decks`
4. **При создании сессии** — пользователь выбирает колоду + порядок (букву A–J). Партнёр на другом устройстве выбирает ту же букву → получает тот же порядок вопросов
5. **Офлайн:** после первой загрузки приложение работает без сети. Все колоды в `localStorage`

Подробнее — в [`docs/SPEC.md`](https://github.com/r3code/random-coffee/blob/main/docs/SPEC.md) основного приложения, раздел §4 «Данные».

## Добавление новой колоды

1. **Создай файл** `decks/<deckId>-<lang>.json` (например, `decks/team-building-ru_RU.json`)
2. **Заполни** по формату выше. Начни с [минимальной колоды](#минимальная-колода), добавь опциональные поля по необходимости
3. **Проверь локально** — можно использовать [линтер из CI](./.github/workflows/build-index.yml) или просто `node -e "JSON.parse(require('fs').readFileSync('decks/your-file.json','utf8')); console.log('OK')"`
4. **Запушь** в `main`
5. **CI проверит** и опубликует. Если есть ошибки — CI упадёт, посмотри лог

### Чек-лист перед коммитом

- [ ] `deckId` соответствует формату и заканчивается на `-<lang>`
- [ ] `name` 1–128 символов
- [ ] Все вопросы имеют уникальные `id` и непустой `text`
- [ ] Все `categoryId` в вопросах существуют в `categories`
- [ ] `deckCategory` (если указан) — из белого списка
- [ ] `orders` (если указан) — все sequence правильной длины, без дубликатов, все IDs существуют
- [ ] `categories` (если указан) — каждый объект имеет `name` и `color`
